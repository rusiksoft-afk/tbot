# Tbot — торговый бот и панель управления для T‑Invest API (Т‑Банк, MOEX)

> **Проект находится в стадии интенсивной разработки и ещё не закончен. Разработка
> продолжается.** Это не готовый продукт: код, схема базы данных и интерфейс меняются от среза
> к срезу, часть подсистем написана, работает на площадке и принята, часть ещё не написана
> или не принята. Торговать этим ботом сейчас нельзя: торговое ядро, исполнитель заявок и
> paper-контур не развёрнуты, а площадка работает в контуре `sandbox`.

Monorepo. С 2026-11-22 репозиторий **публичный** (решение заказчика, `docs/adr/ADR-019`);
пакеты образов в GHCR остаются приватными, `pull` по-прежнему требует токен. Автоматизация
торговли через официальный T‑Invest API: торговое ядро,
веб-консоль (FastAPI + Jinja2 + HTMX), Telegram-управление с 2FA, собственный paper-контур
и бэктест с оптимизатором. PostgreSQL 16, Docker Compose, Python 3.12.

## Что уже работает и чего ещё нет (срез 2026-11-24)

Уже написано, развёрнуто и принято:

- наружный контур `https://tbot.rusiksoft.ru` — `web` + Caddy + PostgreSQL 16 на боевой ВМ,
  TLS с Let's Encrypt, HSTS, HTTP/3; схема базы `0007`;
- допуск и учётные записи: приглашения, пароль, второй фактор (TOTP) и резервные коды,
  блокировка и архив, роли, проверка последней учётной записи администратора;
- журнал `audit_log` с цепочкой хэшей и стражем развилки, его разбор `make audit-verify`
  и ежедневная проверка `integrity-check` (`ADR-025`, `ADR-026`);
- процесс `jobs` на площадке: `integrity-check` цепочки журнала раз в сутки и чистка
  протёкших окон счётчика раз в час (поднят 2026-11-24, `ADR-026`);
- раздел администрирования: список учётных записей, смена роли, сброс второго фактора
  (`ADR-027`);
- CI из 9 job'ов (тесты, `mypy --strict`, покрытие, гейт подавлений, gitleaks по всей истории,

## Потоки и границы (кратко, детали в ТЗ)

```
рыночные данные → стратегия (намерение) → риск-контроль → исполнитель → T‑Invest API
                                              ↓
                             учёт, сверка с брокером, уведомления
```

- Стратегия не имеет доступа к брокеру; торговые вызовы выполняет только процесс `engine`.
- Контуры `sandbox` / `paper` / `production` задаются явно; переход в боевой контур —
  отдельное подтверждённое действие.
- Расчёты только на `Decimal`; заявки — с клиентским ключом идемпотентности и протоколом
  сверки при неопределённом результате.
- Риск-потолки (уровни усреднения, множитель, дневной убыток, доля капитала) зашиты в ядро
  и не могут быть повышены настройкой пользователя.
- В репозитории и истории коммитов не должно быть токенов, ключей, ПДн и упоминаний сторонних
  облачных ботов.

## Команды

```
make dev        # поднимает postgres + web + engine + tgbot + jobs (только sandbox/paper)
make lint       # ruff + mypy --strict
make test       # unit + integration + contract + fault (без боевого API)
make test-live  # только песочница брокера, требует TBOT_SANDBOX_TOKEN
make deploy-check
```

Команды реализованы и исполняются; перечень закрыт `docs/TZ.md §4` и проверяется контрактным
тестом `tests/contract/test_dev_cli_contract.py`. На Windows (где нет `make` и нет Docker) те же
команды идут через `make.ps1` или `py -3 scripts/dev.py <команда>`; реальная проверка контейнеров —
только в CI (`compose-smoke`).
