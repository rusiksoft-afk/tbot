# 09. Веб-консоль: страницы, поведение, дизайн-система

## 9.1 Общие требования

- Серверный рендеринг (Jinja2) + HTMX для частичных обновлений + минимальный Alpine для
  локальной интерактива; никакого SPA-фреймворка. Все ассеты самохостящиеся, без CDN.
- Обновление «живых» блоков — HTMX-опрос раз в 2–5 с (или SSE, если решено в ADR) с явным
  индикатором свежести («данные обновлены 3 с назад», красный при лаге >10 с).
- Оптимистичные UI-состояния для торговых действий запрещены: кнопка → запрос → серверный
  ответ → новое состояние из сервера. Кнопка блокируется на время запроса только визуально.
- Любое разрушающее/торговое действие — модальное подтверждение с указанием объекта
  (счёт, инструмент, объём, контур) и, где требуется, вводом 6-значного TOTP прямо в форме.
- Язык интерфейса — русский; числа: разделитель разрядов тонким пробелом, десятичная запятая,
  валюта «₽» справа, цены — с точностью шага инструмента; время — МСК с подписью «МСК»
  в шапке таблиц и в заголовках графиков; даты — `ДД.ММ.ГГГГ`.
- Адаптивность: desktop-first (1280+), корректная работа на 768 и 390 (управление стратегиями
  с телефона допустимо, но таблицы сжимаются, а не горизонтальный скролл всего экрана).
- Печать/экспорт: печатные стили для отчётов (`@media print`), экспорт CSV/XLSX
  (см. `docs/tz/08 §8.3` про одноразовые ссылки).

## 9.2 Дизайн: «строгий консервативный деловой финансовый»

Норматив для вёрстки (реализуется как CSS-слой `web/static/tbot.css` + классы):

| Аспект | Требование |
|---|---|
| Палитра | фон `#F4F6F8` (светлая) / `#10161D` (тёмная), поверхности `#FFFFFF`/`#18212B`, текст `#14202B`/`#E6EAF0`, линии `#D5DAE0`/`#2A3644`, акцент — приглушённый сине-стальной `#26456A`, ссылки тот же акцент без подчёркивания до hover |
| Семантика | прибыль `#1F6B4A`, убыток `#9E2B2B`, предупреждение `#8A6D1F`, нейтральный `#5B6672`; **плюс** текстовые маркеры «+ / −» и слова, чтобы смысл не зависел от цвета |
| Типографика | IBM Plex Sans (или Inter) для интерфейса, IBM Plex Mono для чисел/кодов/идентификаторов; `font-variant-numeric: tabular-nums` во всех числовых колонках |
| Композиция | плотные таблицы с тонкими разделителями, без «карточек с тенями», без скруглений >4px, без градиентов, без теней (допускается 1px border), без эмодзи и декоративных иконок (иконочный набор — монохромный, 16px, только для действий) |
| Графики | тонкие линии 1.5px, сетка слабая, без 3D/свечения; эквити — одна линия + заштрихованная просадка; свечи — ч/б с красным/зелёным только телом; подписи осей с МСК |
| Тональность текстов | формально-деловая, без «крипто-сленга», без восклицаний, без обещаний доходности; подсказки короткие и технические |
| Состояния | пустое состояние — строка с объяснением и ссылкой на действие; ошибка — код (например `R22`) + объяснение + что делать |
| Доступность | WCAG 2.1 AA: контраст ≥4.5:1 для текста и ≥3:1 для графиков/рамок; focus-visible обязательен; skip-link; tab-порядок логичен; `aria-live="polite"` для обновляемых блоков; подписи форм всегда видимы (не placeholder вместо label); размер цели ≥40×40 на мобильных; `prefers-reduced-motion` — без анимаций |

`REQ-web-01` Дизайн-токены (цвета, отступы, типографика) описаны одним файлом CSS-переменных;
в шаблонах запрещены произвольные hex-цвета и inline-стили (проверка: grep-тест в CI).
`AC-web-01` Ручная приёмка по чек-листу §9.5 + автоматическая проверка контраста
(например `axe-core` в e2e) без замечаний уровня critical/serious.

## 9.3 Карта страниц и обязательное содержимое

**Публичная/входная зона**
1. `/login` — логин, пароль; после успеха → 2. Никаких ссылок на регистрацию.
2. `/totp` — ввод 6-значного кода + ссылка «использовать резервный код»; таймер окна;
   счётчик попыток не показывается (чтобы не помогать перебору), но блокировка объясняется.
3. `/session-expired`, `/locked` (вход заблокирован), `/mfa-enroll` (первичная привязка),
   `/mfa-recovery` (расход резервного кода + предупреждение).

**Профиль и безопасность (любая роль)**
4. `/profile` — имя, логин, роль, e-mail, дата последнего входа, список активных сессий
   (IP, устройство, время) с отзывом.
5. `/profile/security` — статус 2FA, привязка/перепривязка, генерация резервных кодов,
   смена пароля, включение/выключение уведомлений, привязка Telegram (§10.2).

**Администрирование (`admin`)**
6. `/admin/users` — список (роль, состояние, последний вход, 2FA, Telegram), создание
   приглашения, одобрение ожидающих, отзыв приглашения, блокировка/разблокировка, сброс 2FA
   (с TOTP администратора и предупреждением).
7. `/admin/security` — IP-allowlist, глобальный kill-switch (§6.3) с формой причины,
   состояние egress-политики, журнал аудита (фильтры по действию/актору/периоду, выгрузка),
   проверка целостности аудита (кнопка + результат).
8. `/admin/system` — версии (сборка, образ, миграции), статус процессов (engine/web/tgbot/jobs),
   состояние стримов и бюджетов API, размер БД и партиций, очередь уведомлений, ближайшие
   задания, кнопка «перезапустить стратегию/ядро» (с подтверждением), журнал ошибок.
9. `/admin/limits` — системные лимиты (§6.5) с диапазонами; изменение — только с двойным
   подтверждением (TOTP + текстовая константа), отображается журнал изменений.
10. `/admin/instruments` — whitelist инструментов, каталог (лотность, шаг, валюта, статус),
    принудительное обновление каталога.

**Торговая часть (`operator`)**
11. `/accounts` — подключённые токены (маска, состояние, срок до истечения с предупреждением
    за 14/7/3 дня), счета (тип, статус, «разрешён/запрещён для робота» + причина), кнопка
    «проверить токен», «отозвать токен» (останавливает стратегии контура), форма добавления
    токена (§1.3 сценарий 1) с предупреждением о сроке жизни 3 месяца.
12. `/strategies` — таблица: название, инструмент, контур (цветной текстовый бейдж),
    состояние, позиция, P&L дня, просадка, активные заявки, возраст данных,
    «последнее событие»; фильтры; кнопка «создать»; массовые операции (пауза/возобновить —
    без подтверждения, стоп — с подтверждением).
13. `/strategies/new` — мастер: (шаг 1) выбор стратегии и инструмента с поиском по каталогу
    и выводом лотности/шага/валюты/сессии; (шаг 2) выбор счёта и контура (production —
    отдельное предупреждение + TOTP); (шаг 3) параметры формы с валидацией и диапазонами;
    (шаг 4) профиль риска (выделенный капитал, лимиты) + **превью**: сколько уровней,
    максимальный объём, максимальный убыток при срабатывании стопов, требуемые средства;
    финальная кнопка «запустить».
14. `/strategies/{id}` — сводка (капитал, лимиты, позиции, средневзвес, P&L), таблица уровней
    с состояниями, лента событий, журнал отказов риск-гейта (код + причина + снимок),
    график эквити стратегии, действия: пауза, стоп, стоп+закрыть позиции, дублировать
    параметры, архив, «редактировать (требует паузы)», «сменить контур».
15. `/orders` — активные заявки (фильтр по счёту/стратегии/инструменту), сним-«отменить»,
    «отменить все по стратегии»; история заявок с исходами; карточка заявки: клиентский ключ,
    биржевой id, события, комиссии.
16. `/portfolio` — деньги (по валютам), позиции (объём, средняя цена, оценка, P&L,
    доля капитала), блокировки под заявки, маржинальные показатели (если счёт маржинальный),
    расхождения с брокером (`position_mismatches`) с кнопкой «запустить сверку».
17. `/operations` — сделки/операции брокера с фильтрами и экспортом; пометка источника
    (брокер/расчёт системы).
18. `/market` — инструмент: свечи (интервалы), торговый статус и расписание, спред,
    лента отказов; watchlist.
19. `/backtests` — список прогонов, запуск нового (датасет, период, параметры, модель
    исполнения/комиссий), карточка прогона: метрики, таблица сделок, эквити и просадка,
    сравнение двух прогонов, артефакт-манифест данных.
20. `/reports` — отчёты: P&L за период, по стратегиям, комиссии, риск-события,
    «журнал торгов» для личного архива; экспорт; планировщик регулярной отправки дайджеста.
21. `/alerts` — лента оповещений (код, время, область, состояние, подтверждение оператором).
22. `/help` — краткая эксплуатация + ссылки на runbook (для оператора), версия сборки.

`REQ-web-02` Ни одна страница не показывает данные чужого пользователя; админ видит все
учётные записи, но **не** видит открытых токенов (только маску) и не может «подсмотреть»
чужую стратегию в деталях, если это не разрешено настройкой приватности (по умолчанию
операторская стратегия админу видима в части параметров, но не в части токена).

## 9.4 Состояния и ошибки

- Ошибка риск-гейта отображается кодом + человеческим текстом + ссылкой на раздел ТЗ.
- Ошибка брокера (429/5xx) — баннер «работаем в режиме ожидания», без паники, с метрикой лага.
- `DEGRADED`/`HALTED` ядра — красная плашка в шапке всех страниц с причиной и временем.
- Все формы: серверная валидация (pydantic) + клиентная (нативная + HTMX-ответ с полем
  ошибки); значение поля сохраняется при ошибке; сообщения указывают допустимый диапазон.

## 9.5 Чек-лист приёмки интерфейса (ручная проверка, M6)

1. Вход: неверный пароль (5 попыток) → блокировка с объяснением; верный пароль без кода →
   нет доступа; код из прошлого окна → отказ.
2. Все страницы: корректно при 200% увеличении, без обрезки чисел и кнопок.
3. Клавиатура: весь основной сценарий (вход → создать стратегию → пауза → экспорт) проходит
   без мыши; focus виден.
4. Обновление статусов не «дёргивает» скролл и не теряет фокус введённого поля.
5. Экспорт отчёта: файл открывается, содержит только свои данные, имена файлов без ПДн.
6. Печатная версия отчёта читаема (ч/б, без обрезки колонок).
7. Числа: 1 234 567,89 ₽; цена 123,4500 при шаге 0,0001; время «14:05:12 МСК».
8. Цветонезависимость: в скриншоте в оттенках серого прибыль/убыток различимы знаком +/-
   и подписью.
