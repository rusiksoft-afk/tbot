# 13. Тестирование и приёмка

## 13.1 Уровни и размещёние

| Уровень | Где | Что покрывает | Запуск |
|---|---|---|---|
| unit | `tests/unit` | чистые функции: индикаторы, ценовые/лотные расчёты, P&L, метрики, валидация параметров, коды риск-гейта | `make test` |
| property-based | `tests/unit/property` | инварианты округления цен/лотов, монотонность уровней сетки, идемпотентность ключей, отсутствие `float` в расчётах (hypothesis) | `make test` |
| integration | `tests/integration` | работа с PostgreSQL (реальная БД в контейнере), миграции up/down, партиции, `audit_log` append-only, реестр подписок | `make test` |
| contract (gRPC mock) | `tests/contract` | наше обращение к контракту брокера: соответствие request/response моделям текущей версии SDK; воспроизведение записанных сценариев (в т.ч. ошибки 401/403/404/408/429/5xx, частичные исполнения) | `make test` |
| fault-injection | `tests/fault` | обрывы стримов, таймаут посреди `PostOrder`, `kill -9` ядра при активных заявках, отказ БД, истёкший токен, срабатывание kill-switch, «заявка брокера, которой у нас нет» | `make test` |
| e2e web | `tests/e2e` (Playwright) | сценарии входа/2FA/создания стратегии/паузы/экспорта; доступность (axe) | `make e2e` |
| live_api (только песочница) | `tests/live` | реальный контракт с брокером в **песочнице**: подключение, выставление/отмена, сверка, загрузка истории | `make test-live` (вручную/по расписанию) |
| нагрузочный smoke | `tests/load` | 100 подписок + 20 стратегий + веб под 10 пользователями: задержки, память, БД | вручную, перед M7 |

Правило CI: `make lint && make test` обязательны для каждого PR; `make e2e` — для PR,
затрагивающих `apps/web`/шаблоны; `make test-live` — отдельно, по вторникам (песочница),
результат прикладывается к задаче.

## 13.2 Покрытие и качество

- Строгие модули (`risk_gate`, `order_executor`, `strategy_grid`, `indicators`,
  `backtest.metrics`, `credentials`): **покрытие ≥ 90%** строк и обязательные сценарные тесты.
- Остальное: ≥ 80%. Общий порог CI — 80%, падение ниже — блокировка слияния.
- `mypy --strict` без исключений в `packages/**`; `# type: ignore` допускается только со
  ссылкой на ADR в той же строке.
- Запрещено: удалять/скипать тесты ради зелёного CI (проверка диффа: `@pytest.mark.skip`,
  `xfail`, понижение порогов покрытия — требуют явного обоснования в описании PR и
  одобрения).

## 13.3 Обязательные «красные» тесты (регрессии, которые должны быть написаны)

1. `PostOrder` вызывается ровно один раз на намерение; при таймауте — ни одного повторного
   вызова (`docs/tz/07 §7.4`).
2. Идемпотентность: два одинаковых намерения в окне дедупликации → одна заявка.
3. Стратегия не может позвонить брокеру напрямую (тест архитектуры/импортов).
4. Риск-гейт отклоняет: закрытый рынок, устаревшие данные, нехватка средств/лота,
   непокрытая продажа без флага, превышение дневного убытка, превышение уровней сетки,
   «неизвестная» заявка по инструменту.
5. Восстановление после `kill -9` не создаёт дублей и не теряет уровни.
6. Расхождение позиции → изоляция инструмента и запрет новых заявок.
7. Бэктест не использует будущие данные (тест с «отравленным» баром в будущем: сигнал не
   меняется).
8. Воспроизводимость бэктеста (повторный прогон — тот же результат).
9. Токен не попадает в логи/дампы (логирование канарейки).
10. Вход без TOTP невозможен; перебор кодов блокируется; резервный код одноразовый.
11. `operator` не получает доступ к чужим данным (404/403 без утечки).
12. Kill-switch исполняется ≤2 с, отключается только с TOTP.
13. Смена контура стратегии не меняет её историю и требует подтверждения.
14. Увеличение риск-лимита выше диапазона невозможно без админ-режима и даёт запись в
    `risk_events`.

## 13.5 Учения (обязательный прогон перед M7, с протоколом)

1. **Обрыв стрима котировок** (обрать соединение на 90 с) → переподключение, догрузка свечей,
   отсутствие ложных сигналов, алерт.
2. **Таймаут заявки** (mock/песочница: не отвечать 5 с) → состояние `unknown`, сверка,
   одна заявка у брокера.
3. **Жёсткая остановка ядра** при 5 активных уровнях → рестарт, полная сверка, отсутствие
   дублей/отмен.
4. **Отзыв токена у брокера** (в песочнице) → стратегии в `blocked_by_risk`, алерт, отсутствие
   попыток «пробить» ошибку.
5. **Срабатывание дневного лимита убытка** (проверить в песочнице с малым лимитом) →
   запрет новых сигналов, объяснение в UI/чат, разблокировка только вручную.
6. **Восстановление из бэкапа** на отдельном стенде → контрольные запросы сходятся,
   `audit-verify` без разрывов.
7. **Атака на вход** (перебор паролей и кодов, 100 запросов) → блокировки, бан IP,
   уведомления, отсутствие обхода.

Протокол учения (кто, когда, результат, снимки/логи) хранится в `docs/acceptance/`.

## 13.6 Критерии «готово» для каждой вехи

- M0: поднят `make dev`, CI зелёный, миграции up/down, health-checks, базовые метрики.
- M1: вход с 2FA, роли, приглашения+одобрение, шифрование токенов, аудит, IP-allowlist, TLS.
- M2: каталог+данные в БД, стримы, загрузчик истории, бюджеты запросов, метрики брокера.
- M3: песочница — полный цикл выставления/отмены/сверки, риск-гейт со всеми кодами,
  kill-switch, `unknown`-протокол.
- M4: стратегии в `paper` ≥10 торговых дней без нарушений, уведомления + дайджест.
- M5: бэктест с манифестом, метриками, walk-forward, предупреждениями; воспроизводимость.
- M6: веб-консоль полностью (все страницы §9.3), Telegram-управление с подтверждениями, отчёты.
- M7: учения §13.5 пройдены, боевой запуск с консервативными лимитами на 1 инструменте,
  мониторинг и бэкапы работают, runbook проверен.
