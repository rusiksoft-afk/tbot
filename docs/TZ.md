## 1. Назначение

**Цель.** Дать оператору (владельцу счёта) инструмент круглосуточной автоматизации торговли
на MOEX через официальный T‑Invest API: размещать и сопровождать заявки по правилам стратегии,
контролировать риск в реальном времени, видеть позиции и P&L, получать оповещения и
управлять ботом из браузера и из Telegram.

**Что бот делает:** получает рыночные данные и состояние счёта, вычисляет сигналы стратегии,
пропускает намерения через детерминированный риск-контроль, размещает/заменяет/отменяет заявки,
ведёт собственный учёт и сверяется с брокером, оповещает оператора, предоставляет веб-консоль
и Telegram-интерфейс, позволяет проверить стратегию на истории (бэктест) до запуска.

**Чего бот не делает (осознанно, см. §12 и `docs/tz/15`):** не переводит деньги между счетами,
не выводит средства, не покупает/продаёт вне настроенных инструментов и сессий, не является
индивидуальной инвестиционной рекомендацией, не обещает доходность, не работает в режиме HFT
(публичный API не предназначен для микроструктурной торговли: десятки–сотни миллисекунд до
брокера), не хранит и не передаёт токены третьим лицам.

**Успех (верхнеуровнево, детали в `docs/tz/13`):**
1. Ноль «лишних» заявок: ни одна заявка не появляется без решения риск-контроля; повторная
   отправка при таймауте не создаёт дубль (подтверждается тестами и учением в песочнице).
2. Ограниченный риск: дневной убыток и объём позиции не превышают настроенные лимиты;
   kill-switch останавливает новые сигналы и, по команде, снимает открытые заявки.
3. Восстановимость: после перезапуска процесса/сервера бот восстанавливает состояние заявок
   и позиций из БД + сверки с брокером без ручных правок.
4. Наблюдаемость: оператор за 30 секунд видит, что происходит с каждой стратегией, и может
   поставить её на паузу/остановить из веб-консоли или Telegram.
5. Данные не врут: P&L, комиссии и позиции в системе сходятся с выгрузкой брокера на контрольной
   дате (расхождение — только объяснённый журнал).

## 6. Стиль кода (образец)

Конвенции: snake_case для модулей и функций, PascalCase для моделей, константы UPPER_SNAKE;
модуль = одна ответственность из карты; никаких «божественных» классов; тайп-хинты обязательны,
`mypy --strict` зелёный; докстринги — что и почему, без копирования документации брокера;
комментарии на русском; длина функции ≤ 60 строк, сложность ≤ 12; все внешние вызовы — через
адаптеры (`broker_gateway`), никаких «сырых» grpc-вызовов в стратегиях.

```python
# packages/strategy_grid/pricing.py
from decimal import ROUND_DOWN, ROUND_UP, Decimal

from packages.instrument_catalog.model import InstrumentSpec
from packages.common.money import QuotationLike


def clamp_limit_price(raw: Decimal, spec: InstrumentSpec, side: str) -> Decimal:
    """Ограничивает цену лимитной заявки допустимым шагом инструмента.

    Покупка округляется вниз к шагу, продажа — вверх: заявка не должна случайно
    пересечься с чужим стаканом шире, чем задумано стратегией.
    """
    if spec.min_price_increment <= 0:
        raise ValueError(f"инструмент {spec.instrument_uid} не имеет шага цены")
    steps = (raw / spec.min_price_increment).to_integral_value(
        rounding=ROUND_DOWN if side == "buy" else ROUND_UP
    )
    price = (spec.min_price_increment * steps).quantize(spec.min_price_increment)
    if price <= 0:
        raise ValueError(f"цена {raw} после нормализации стала {price}")
    return price


def order_quantity_lots(capital: Decimal, price: Decimal, spec: InstrumentSpec) -> int:
    """Количество лотов: только целое, только в рамках выделенного капитала."""
    if price <= 0 or capital <= 0:
        return 0
    lots = int(capital / (price * spec.lot))          # лот = lot штук по цене
    if lots <= 0:
        return 0                                      # заявка меньше лота — не отправляем
    return lots
```

Запрещено (проверяется линтерами/ревью, см. `docs/tz/15`): `float` для денег и цен; ручная
сборка `units`/`nano`; `datetime.now()` без часового пояса (только `common.clock.now_utc()`);
`print`; перехват всех исключений «голым `except:`»; прямой вызов `post_order` из стратегии; добавление
`@rtype: ignore` / `# noqa` / `# type: ignore` без строки обоснования и ссылки на ADR.

## 7. Границы разработки (кратко; полный список — `docs/tz/15`)

- **Всегда:** тесты до коммита; миграция на каждое изменение схемы; логирование без секретов;
  сверка с документацией API при изменении контракта; ADR на архитектурное решение.
- **Сначала спросить:** новая зависимость; изменение схемы БД без миграции; изменение
  риск-лимитов по умолчанию; новый метод T‑Invest API в `broker_gateway`; изменение CI;
  любые действия на прод-сервере; любые вызовы боевого контура из тестов.
- **Никогда:** коммит токенов/ключей/ПДн; обход риск-гейта; автоповтор `PostOrder` без сверки
  по клиентскому ключу; `float` в денежных расчётах; включение боевого контура изменением кода
  (только конфигурация + подтверждение 2FA); правки сгенерированных gRPC-стабов; упоминание
  сторонних облачных ботов-референсов в коде, README, комментариях, истории коммитов.

## 8. Критерии готовности релиза M1 (детали — `docs/tz/13`)

1. Песочница: полный цикл «старт стратегии → уровни в таблице → исполнение → цель по позиции →
   закрытие» проходит без ручных вмешательств; все заявки имеют клиентские ключи и след.
2. Боевой контур малых объёмов: ≥10 торговых дней без нарушений лимитов и без «потерянных» заявок.
3. Приёмочные учения: разрыв стрима, таймаут заявки посреди выставления, рестарт ядра при
   открытых заявках, истёкший токен, сработавший kill-switch — все шесть сценариев дают
   документированное поведение.
4. Веб-консоль и Telegram: вход только с TOTP; управляющие команды требуют подтверждения;
   суточный дайджест приходит вовремя.
5. Бэктест: для эталонной конфигуции воспроизведён один и тот же результат при повторном запуске
   (совпадают метрики и набор сделок), манифест данных записан.
6. CI зелёный: линтеры, `mypy --strict`, тесты, `pip-audit`, `gitleaks` — без исключений.
