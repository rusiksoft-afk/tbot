## Требует перепроверки перед соответствующей вехой

1. **Версия и контракт `t-tech-investments`.** Пакет обновляется часто (на момент проверки —
   1.51.0). Перед M2 зафиксировать версию пин-паком и прогнать contract-тесты; при обновлении —
   повторять contract-тесты и учение в песочнице (TZ §15.4).
2. **Поведение песочницы**: эмуляция исполнения, частичные исполнения, доступность стоп-заявок,
   лимиты на эмулятор — проверяются экспериментально на M3 (`make test-live`), а не по документации.
3. **Доступность API с точки прод-размещения и TLS** (сертификат НУЦ): conformance-тест с VPS
   перед M2/M7 (TZ §14.5 п.1). **Часть закрыта 2026-11-20:** обе точки доступны с рабочей ВМ,
   цепочка доверяется после установки корня НУЦ, неавторизованный вызов даёт `401`
   (`docs/acceptance/prod-bootstrap.md §2`). Остаётся часть с авторизованным токеном:
   проверка контракта, лимитов и задержек с реальным ключом — на M2/M7.
4. **Лимиты**: таблица лимитов может измениться; перед M2 сверить с актуальной страницей лимитов
   и обновить `docs/tz/03` + бюджеты в коде (это «спросить-before-change» по TZ §15.1).
5. **Расписания торгов и торговые статусы**: берутся только из API, локальные предположения
   запрещены (OQ-7).
6. **Комиссии тарифа пользователя**: API их не отдаёт; значения вводит оператор, перепроверять
   при смене тарифа (OQ-3, `configs/commissions.yaml`).
7. **Характеристики стенда и прод-VPS**: снять заново при подключении (`nproc`, `free -h`,
   `df -h`, `docker --version`) — цифры в `docs/tz/14` от 2026-11-18.

## Правовые формулировки

Раздел `docs/tz/15 §15.2–15.3` описывает технические следствия (дисклеймеры, минимизация ПДн,
размещение в РФ, отсутствие платёжного модуля) и **не является юридической консультацией**.
Тексты согласий/политик и оценку правомерности режима «закрытый клуб» даёт владелец проекта с
юристом до подключения первых внешних пользователей (OQ-9, план §6).
